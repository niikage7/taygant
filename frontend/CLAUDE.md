# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This is the **frontend** package of the `taygant` monorepo (a Gantt-chart-based project management app). Only this `frontend/` directory should be edited — the sibling `backend/` (Go) is out of scope: read it for API context, never write to it.

This project pins a Next.js version with breaking changes relative to training data — APIs, conventions, and file structure may differ. **Before writing any Next.js-specific code** (routing, data fetching, config), read the relevant guide under `node_modules/next/dist/docs/` and heed any deprecation notices. `AGENTS.md` in this directory carries the same instruction and is auto-regenerated by `next dev`; don't fight it if it reappears after being removed.

## Environment

`.env` requires `BACKEND_URL` (e.g. `http://localhost:4000`), pointing at the Go backend. It is consumed only by `next.config.ts` at build/dev time (server-side rewrite), never exposed to the client directly.

## Architecture

### Backend proxying

The app never calls the backend origin directly from the browser. `next.config.ts` rewrites `/backend/:path*` → `${BACKEND_URL}/:path*`. The backend mounts its API under `/api/v1` (see `backend/api-spec.yml`), so all frontend requests go through `/backend/api/v1/...`. This keeps `BACKEND_URL` server-only and avoids CORS.

`BACKEND_URL` has a fallback (`http://localhost:4000`) — без него незаданная переменная давала бы destination `undefined/api/v1/...`, и rewrite ломался бы молча.

**Определение IP клиента.** `src/proxy.ts` срезает `X-Forwarded-For`, `X-Real-IP`, `X-Client-IP` и `Forwarded` на пути `/backend/*`. Причина проверена экспериментально: rewrite прокидывает заголовки браузера в destination как есть (запрос с `X-Forwarded-For: 203.0.113.9` доходит до бэкенда с этим значением), а адрес Next входит в `TRUSTED_PROXIES` бэкенда — то есть клиент мог бы подменить себе IP и обойти rate limit. Свой `X-Forwarded-For` Next не добавляет, реального адреса клиента он не знает, поэтому достоверного IP через эту схему не получить в принципе — бэкенду не следует ключевать лимиты по IP, пока перед Next не появится настоящий обратный прокси. Если такой прокси появится, логику в `proxy.ts` нужно пересмотреть.

⚠️ В Next 16 `middleware.ts` переименован в **`proxy.ts`** (экспорт функции `proxy`) — старое имя устарело.

### API layer (`src/services/`, `src/types/`)

The backend's OpenAPI spec lives at `backend/api-spec.yml` (read-only reference — it is the source of truth for request/response shapes). The frontend mirrors it:

- **`src/types/`** — one file per domain (`project.ts`, `task.ts`, `dependency.ts`, `checklist.ts`, `comment.ts`, `history.ts`, `gantt.ts`, `simulation.ts`, `workload.ts`, `dashboard.ts`, `member.ts`, `sprint.ts`, `milestone.ts`, `user.ts`, `auth.ts`, `export.ts`, `common.ts` for shared enums), re-exported through `src/types/index.ts`. Types are named after the OpenAPI schemas (`Task`, `TaskDetail`, `TaskCreateRequest`, `TaskUpdateRequest`, etc.) so they can be cross-referenced with `api-spec.yml` directly.
- **`src/services/`** — one service per OpenAPI tag (`auth`, `users`, `projects`, `members`, `sprints`, `milestones`, `tasks`, `dependencies`, `checklist`, `comments`, `history`, `simulation`, `workload`, `dashboard`, `export`), each a plain object of methods that call `httpClient`. Re-exported through `src/services/index.ts`.
- **`src/services/http-client.ts`** — the single fetch wrapper all services go through. Key behaviors to preserve when extending it:
  - Base path is `/backend/api/v1`.
  - Access token is kept in memory + `localStorage` (`setAccessToken`/`getAccessToken`); `Authorization: Bearer` is attached automatically unless `{ auth: false }` is passed (used by `/auth/login` and `/auth/refresh`).
  - Errors throw `ApiError` (has `status` and parsed `body`), not raw `Response`.
  - `204 No Content` responses resolve to `undefined`.
  - Binary responses (PDF/XLSX export) use `httpClient.getBlob`, not `get`.

When adding a new endpoint: add/extend the type in `src/types/`, add the method to the matching service in `src/services/`, and keep both in sync with `backend/api-spec.yml`.

### App structure

Standard Next.js App Router under `src/app/` (currently just the root `layout.tsx`/`page.tsx`). Path alias `@/*` maps to `./src/*` (see `tsconfig.json`).

`next.config.ts` has `reactCompiler: true` enabled — avoid manual `useMemo`/`useCallback` micro-optimizations that fight the compiler; write plain component code.

### Дизайн-система

Макеты лежат вне репозитория (SVG-экраны: авторизация, регистрация, дашборд, Гант, редактор задачи, мастер проекта). Токены сняты с них напрямую и живут в `src/app/globals.css` в блоке `@theme` (Tailwind v4, без `tailwind.config`):

- **Цвета** — семантические имена, а не шкалы: `brand` (#004AC6) + `brand-hover/active/tint/chip/soft`, `accent` (индиго #4648D4), поверхности `page` (#F8F9FF) / `surface` / `surface-muted` / `surface-subtle`, границы `line` / `line-strong`, текст `ink` / `ink-muted` / `ink-faint`, статусы `success` / `warning` / `danger` (+ `-tint` варианты для подложек).
- **Радиусы** — в макете ровно два: `rounded-control` (4px, поля/кнопки/чипы) и `rounded-card` (8px, карточки). Не вводить произвольные значения.
- **Тени** — `shadow-card` и `shadow-popover`.
- **Шрифты** — Inter (`font-sans`) и JetBrains Mono (`font-mono`, для ID, дат, кодов задач — в макете моноширинный используется как смысловой акцент). Подключены в `src/app/layout.tsx` через `next/font/google` с подмножеством `cyrillic`.
- **Фокус** — утилита `focus-ring`, применяется как `focus-visible:focus-ring`.

Тёмной темы в макетах нет — дизайн-система намеренно светлая.

### Маршруты авторизации

`src/app/(auth)/` — группа с общей оболочкой (фон #F8F9FF с размытыми пятнами, карточка 420px, копирайт): `/login`, `/register` и `/forgot-password`.

`/forgot-password` — заглушка: ссылка есть в макете входа, но сброса пароля нет ни в `api-spec.yml`, ни в хендлерах (только login, register, refresh). Страница объясняет, что делать, чтобы ссылка не вела в 404.

**Карта маршрутов.** `/` редиректит на `/overview`; оболочка `(app)` без токена отправляет на `/login`, поэтому неавторизованный с корня попадает на вход одной цепочкой. После входа и регистрации — `/overview`. `src/app/not-found.tsx` ловит и опечатки в адресе, и ссылки на удалённые задачи.

Пункт сайдбара «Детали и Зависимости» ведёт на первую задачу проекта и остаётся неактивным, пока задач нет: жёстко зашитый идентификатор задачи сломался бы на любом реальном проекте.

⚠️ `POST /auth/register` **намеренно отсутствует в `api-spec.yml`**, но реализован сверх спецификации — сверяться нужно с `backend/internal/api/auth.go` (тело: `email`, `password`, `fullName`, `department`, `position`; ответ 201; 400 — данные, 409 — email занят).

Правила пароля продублированы на клиенте в `register-form.tsx` и обязаны совпадать с `auth.ValidatePassword` (`backend/internal/auth/password.go`): 8+ символов, не длиннее 72 байт, минимум одна буква и одна цифра. При изменении правил на бэкенде править и схему zod.

`/terms` — пользовательское соглашение. Текст лежит в `src/content/terms.md` и **является источником правды**: чтобы обновить документ, правится markdown, вёрстку трогать не нужно. Страница статическая, файл читается через `fs` во время сборки. Рендер — `components/content/markdown.tsx` (react-markdown с картой компонентов на токенах дизайн-системы; плагин `@tailwindcss/typography` намеренно не подключён, он приносит свою шкалу цветов и отступов). Подключён `remark-breaks`: одиночные переносы строк становятся `<br>`, иначе строки вроде «Дата публикации» и «Редакция» склеивались бы в одну.

Ссылка на соглашение со страницы регистрации открывается в новой вкладке — уход со страницы стёр бы уже заполненную форму.

Ссылка `/forgot-password` — заглушка, страницы пока нет.


### Внутренние экраны

`src/app/(app)/` — группа с общей оболочкой (`components/app/sidebar.tsx` + `top-bar.tsx`): `/overview` (дашборд состояния и рисков), `/gantt` (диаграмма Ганта), `/tasks/[taskId]` (редактор задачи и симулятор каскадного сдвига), `/projects/new` (мастер инициации проекта).

Данные идут через React Query — хуки в `src/data/queries.ts` поверх сервисов. Провайдер в `src/app/providers.tsx` (QueryClient создаётся в состоянии, а не в модуле: на сервере модульная переменная была бы общей для всех запросов). Оболочка `(app)/layout.tsx` — клиентская: без токена сразу редиректит на `/login`, не дожидаясь 401.

**Текущий проект** живёт в контексте `src/data/current-project.tsx` и сохраняется в localStorage, чтобы выбор переживал переходы между разделами. Сохранённый id сверяется со списком с сервера: проект могли удалить или отобрать доступ. Переключатель — `components/app/project-switcher.tsx` в карточке проекта внизу сайдбара; при одном проекте это просто сводка без выпадающего списка.

**Связи проекта** собираются в `useProjectDependencies`: эндпоинта «связи проекта» нет, есть только связи задачи, поэтому задачи опрашиваются параллельно и у каждой берутся её предшественники — каждое ребро принадлежит ровно одной задаче как входящее, дубликатов не возникает.

⚠️ **Что ещё не готово на бэкенде** (возвращает 501): только `workload` и `export`. `dashboard` и `simulation` реализованы.

Обзор берёт данные из `GET /projects/{id}/dashboard`. Два поля бэкенд заполнить не может и честно об этом пишет в комментарии к хендлеру: `progressDeltaPercent` всегда 0 (нет исторических снимков прогресса) и `teamWorkload` всегда пуст (в задачах нет оценки часов). Поэтому дельта не показывается вовсе, а карточка загрузки рендерится только при непустом списке.

**Группировка реестра Ганта.** Порядок строк считается один раз в `src/lib/gantt-rows.ts` (`buildGanttRows`) и отдаётся и таблице, и таймлайну — иначе отрезки уехали бы относительно названий. Задачи вложены под веху с отступом, веха сворачивается. Принадлежность берётся из `task.milestoneId` — настоящего поля модели (бэкенд добавил его по запросу). Прежняя эвристика по связям убрана: веха агрегирует работы, а зависимости описывают порядок их выполнения — это разные вещи и живут в разных блоках карточки задачи.

**Две разные сущности «веха».** `Milestone` — обязательство проекта по дате (таблица `milestones`, без связи с задачами); `Task.isMilestone` — элемент графика нулевой длительности, обычная задача со связями. На таймлайне Ганта показываются обе, в легенде разведены. Привязать задачу к `Milestone` нельзя — в модели задачи нет такого поля; группировка задач идёт через `SprintID` и `ParentTaskID`.

Статус вехи вычисляется сервером из `actualDate` (`deriveMilestoneStatuses`), отдельного поля «статус» в запросе нет: «отметить достигнутой» — это простановка фактической даты, снятие отметки — явный `null`. При редактировании названия или даты `actualDate` **не передаётся** — на бэкенде «не передано» значит «не менять», иначе правка сбрасывала бы отметку. Та же семантика у `TaskUpdateRequest.milestoneId`.

Контрольные точки создаются, редактируются и удаляются в `components/dashboard/milestones-dialog.tsx` — он открывается кнопкой в заголовке полосы вех на обзоре. Диалог работает по полному списку `GET /projects/{id}/milestones`, а не по `nearestMilestones` из дашборда: тот отфильтрован от завершённых и обрезан до трёх, поэтому созданная веха могла бы в него не попасть и это выглядело бы как несохранение.

Экран Ганта берёт задачи, связи и вехи одним запросом `GET /projects/{id}/gantt` (`useGantt`). Раньше маршрута не было и связи собирались обходом задач — этот обход убран.

Карточка задачи умеет: редактирование (название, ответственный, статус, даты, прогресс, описание — PATCH одним запросом по накопленному черновику), критерии приёмки с добавлением и удалением, вкладки истории и комментариев, создание и удаление связей, переход по связи на другую задачу, what-if симулятор сдвига (`simulate-shift` и `apply-shift`) и копирование ссылки кнопкой «Поделиться».

Задачи создаются диалогом `components/gantt/create-task-dialog.tsx` — он вызывается и из шапки, и с экрана Ганта. Предшественник указывается сразу: бэкенд принимает связи в теле создания, это избавляет от шага «создать, потом связать».

`TaskUpdateRequest.assigneeId` — `string | null`: `null` снимает ответственного, отсутствие поля оставляет прежнего (на бэкенде `*uuid.UUID`).

Геометрия Ганта — `src/lib/gantt.ts`: диапазон, колонки месяцев/недель/дней и перевод дат в пиксели. Отрезки и SVG-стрелки связей считаются в одной системе координат от начала диапазона, поэтому не разъезжаются при прокрутке и смене масштаба. «Сегодня» передаётся в `Timeline` пропом, а не берётся из `new Date()` внутри компонента — иначе сервер и клиент отрисовали бы разные даты и получилась бы ошибка гидратации.

Подсветка красным в реестре задач означает «критический путь **и** есть отставание», а не просто принадлежность критическому пути: в макете из четырёх этапов критического пути выделена одна строка — та, что требует вмешательства.
